# 2회차 — Linux bridge: VM 바로 옆에서 끊기면

> 세션: 2026-11-02 (월) 22:00 디스코드 · 제출 마감: 2026-11-01 (일) 23:59

## 0. 시작 전 확인

실습 환경 접속 가이드(노션)의 **10번 체크리스트**를 **수요일(10/29)까지** 완료하고 카톡방에 "완료"라고 답해주세요.
체크리스트는 vm1 접속과 vm1→vm3 ping까지입니다. **vm2 접속 실패는 이번 주 과제이니 정상입니다.**

## 2. 장애 신고

> **신고자:** 스터디원

> **내용:** 어제까지 잘 되던 **vm2에 SSH 접속이 안 됩니다. ping도 안 갑니다.** vm1은 똑같은 방법으로 잘 들어가지고, Horizon에서 vm2는 ACTIVE로 보입니다. 제가 건드린 건 없습니다.

**대상**

- 프로젝트: `study-<본인ID>`
- 관련 리소스: `<본인ID>-vm2` (증상, cmp02에서 실행 중), `<본인ID>-vm1` (비교용, cmp01)

**참고**

- 원인은 **한 군데**이고, 사람마다 다를 수 있습니다. 옆 사람 답이 내 답이 아닐 수 있습니다.
- Grafana(`localhost:3001`)에서 본인 vm2 FIP 프로브가 언제부터 어떻게 보이는지 확인해보세요.

## 3. 요구

ops01(FIP) → net01 → cmp02 → vm2 까지 **패킷이 지나는 지점을 순서대로 확인**하고, 어느 지점에서 끊기는지 짚으세요.
끊긴 지점을 찾았으면 왜 그 지점이 이 증상으로 나타났는지, 그리고 **어떻게 고치면 되는지** 설명하세요. 복구는 실행하지 말고 세션에서 운영진이 합니다.

## 4. 확인 지점 체크리스트

위에서부터 순서대로 좁혀가세요. 각 지점에서 **무엇을 확인했고 결과가 어땠는지**를 제출물 3번에 남깁니다.

| # | 지점 | 쓸 만한 명령 |
| --- | --- | --- |
| ① | OpenStack이 보는 vm2 포트·FIP 상태 | `openstack port list --server <본인ID>-vm2` · `openstack port show <포트ID>` · `openstack floating ip list` |
| ② | 시큐리티 그룹 규칙 — ping이 안 되는 이유와 SSH가 안 되는 이유가 **같은지 다른지** | `openstack security group rule list <본인ID>-sg` |
| ③ | net01의 라우터 네임스페이스에서 vm2 내부 IP로 직접 ping / tcpdump | `sudo ip netns list` · `sudo ip netns exec qrouter-<ID> ping <vm2 내부IP>` · `sudo ip netns exec qrouter-<ID> tcpdump -ni any icmp` |
| ④ | cmp02에서 vm2의 tap → qbr → qvb/qvo → br-int 연결 상태 | `ip link` · `brctl show` (없으면 `bridge link`) · `sudo docker exec openvswitch_vswitchd ovs-vsctl show` |
| ⑤ | 끊긴 지점이 왜 "SSH도 ping도 안 됨"으로 보였는지 한 줄 설명 | |

> 포트 ID 앞 11자리가 `tap`·`qbr`·`qvb`·`qvo` 뒤에 붙습니다. ①에서 포트 ID를 먼저 확보하면 ④에서 바로 찾을 수 있습니다.

## 5. 해결 조건

- 끊긴 지점을 특정하고 원인을 한 문장으로 설명할 수 있을 것
- 복구 방법을 적을 수 있을 것 (실행은 하지 않음)
- (못 풀었다면) 어디까지 확인했고 어디서 막혔는지 기록이 있을 것

## 6. 규칙

- 진단(조회·tcpdump·네임스페이스 안에서 ping)은 자유, **설정 변경·복구는 하지 않습니다**
- 컨테이너 재시작 · reconfigure · 시큐리티 그룹 변경 · FIP 재할당 · `ip link` / `ovs-vsctl`로 상태 바꾸기 금지 — 공용 노드라 다른 사람 환경에 영향이 갑니다
- 노드 접속은 본인 계정으로만
